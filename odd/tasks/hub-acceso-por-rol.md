# hub-acceso-por-rol

Objective: confine `director_nivel` and `operador_establecimiento` to their own areas, make resources allow-list, and centralize access so a change cannot silently break other flows.
Branch: `GeronimoSerial/hub-encierro-roles` (from `origin/main`). Delivery: ask-on-risk. Runner: `npm test` (vitest, colocated `*.test.ts(x)`).

## Specs

- S1 (L2): A user who is "director de nivel o director de establecimiento" must not see the hub: "deben estar encerrados". Includes not reaching Inicio (`/`), `/explorar`, recursos, tableros, `/api/hub`, `/api/gate`.
- S2 (L2): "quiero que los recursos se PERMITAN ver a ciertas personas, no ocultar a ciertas. Al reves." A non-staff user opens a resource only when explicitly permitted (user, nivel jurisdiccional, or assigned recurso list). No audience means staff only.
- S3 (L2): "hay un login inicial asi que tambien tenelo en cuenta." The existing hub login gate (`app/(hub)/layout.tsx`, `lib/hub-entry.ts`) keeps working; after login each confined role lands in its own area even if `callbackUrl` points to the hub.
- S4 (L5): `director_nivel` keeps `/mapas/infraestructura`, `/mapas/infraestructura/escuelas/[cue]`, `/infraestructura/cargar` ("Si, deberia poder") and every API those pages call. `operador_establecimiento` keeps `/problematicas/parte/*`, its APIs, the service worker, and the materiales offered after save.
- S5 (L4): no API needed by the normal flows may break ("estamos seguros que hacer esto no puede provocar que alguna otra api ... falle"). The infra map must not depend on the audience of recurso `/mapas/infraestructura` for confined roles.
- S6 (L5): "Realiza una abstraccion que permita mejorar la arquitectura actual y en el futuro no repetir el problema de que si cambio algo se rompen distintas cosas sin saberlo."
  - Design (proposed): one access module `lib/access/` with a single role -> capability policy, and a route manifest that declares the capability every page and `app/api/**/route.ts` requires. Pages, layouts and APIs check through it instead of ad hoc `puedeAbrir` / section checks.
  - Guard tests: (a) a manifest test fails when any route file has no declared capability; (b) a role x route matrix test pins who reaches what, so any change in reach shows up as a failing diff.
- S7 (L8): "Quedan ocultos." Published resources without audience become staff-only on deploy; admin enables them.
- S8 (L9): "El mapa de infraestructura por nada del mundo debe perder su acceso." The infra map is exempt from the allow-list: consulta keeps today's rule for recurso `/mapas/infraestructura` (no audience = open with the infrastructure section); directors keep it by capability. (L10) "O generar una problematica": creating a problemática (parte flow `/problematicas/parte/*`, `/infraestructura/cargar`, their APIs and `sw-parte.js`) must never lose access either; it is outside `puedeAbrir` and must stay so, pinned by tests.
